The multi-agent AI engine

An orchestrator that takes a request, picks the best-suited AI model, splits the work into parallel tasks and switches to another provider on its own when one goes down. It was born to drive my Home Assistant display.

"Async multi-agent LLM orchestrator with Elo routing, self-healing, and an OpenAI-compatible Proxy API. Built for Home Assistant, usable everywhere."

What it does

Pick the right model

Four-stage routing: simple rules, a small classifier, a model's opinion, then an Elo score that learns from use which model succeeds at which kind of task.

Work in parallel

A complex request becomes a graph of tasks run at the same time (asyncio).

Heal itself

Circuit breakers, spaced retries, failover to another provider depending on availability and budget.

Remember

Local document search (TF-IDF, BM25 and ChromaDB) to answer with the house's context.

Talk to your tools

An OpenAI-compatible API (/v1/chat/completions) usable from Cursor, Cline or Continue, and routes dedicated to Home Assistant.

Stay in control

Human approval of sensitive actions, a plugin system, remote workers and a dashboard (FastAPI and React).

Under the hood

  • Python 3.11+, FastAPI, asyncio, SQLite, ChromaDB, scikit-learn; dashboard in React, Vite and TypeScript.
  • 13 supported AI providers, in the cloud (Gemini, GitHub Models, DeepSeek, Anthropic, Mistral, OpenRouter…) or local (LM Studio, Ollama).
  • Four documented configuration strategies, a Docker image and docker-compose, pytest tests and continuous integration.

A personal tool shared as is: the dashboard still has rough edges, and no release is published yet.
